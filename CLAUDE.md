# EE Labs Simulator — محاكي معامل قسم الكهرباء

A static website (GitHub Pages, no server, no login) that simulates the EE department labs at King Saud University as a reference for students. Start: EE312 (Basic Electronics Lab). Later: ~8 labs × ~10 experiments.

## Source of truth
- `docs/<lab>/` holds the lab manual and slides (PDF/images). Every experiment MUST match them exactly: same instruments, same component values, same procedure steps, same figures, same questions.
- If the manual and these rules disagree, follow the manual and tell the user.
- Never invent instruments or steps. Component behaviour and readings are **yours to derive**: use the manual, the slides, the parts' datasheets and device physics to choose realistic models and values (e.g. a 1N4001 reads ≈0.55 V on diode test, a Ge point-contact diode ≈0.2–0.3 V, a green LED ≈1.7–2 V). Do not ask the user for numbers. Fallback only: if a value is still unclear after the manual, slides and datasheets, use the student's own lab reports in `docs/<lab>/measured/` (may contain mistakes).
- Resolve small gaps yourself (typos in figure numbers, one meter vs two drawn in a figure, unnamed parts) with the most reasonable reading of the manual and slides, note your assumption in the commit message, and keep going. Ask the user only when the manual and slides genuinely contradict each other on something that changes what the student does.

## Current state
- The site is split into `engine/` (shared) and `labs/` (one file per experiment). `index.html` only holds the shell markup and script tags.
  - `engine/solver.js` circuit solver (Newton dc op, quasi-static sweep for the generator, transient for C / transformer / op amps starting from the dc operating point; several floating supply units with CV/CC; meter test source). Device models: diodes (Si, Zener, Ge, LED), µA741 macro-model, IRF620 (FET), BD137 (BJT), inductors and ideal coupled transformers (for the PC simulator).
  - Instruments: `scope.js` (GDS-1104B, 4 channels), `gen.js` (PeakTech 4124), `psu.js` (TTi EL302RD, two units, per-experiment knob resolution), `dmm.js` (MCP MT3805; numbered meters `n:1/2` → keys `dmm`/`dmm2`, leads `mh ml`/`m2h m2l`; labs read them through `RT.meters()` / `RT.meterOn(a,b)`), `xf.js` (center-tapped transformer), `dbox.js` (two resistance decade boxes).
  - `board.js` bench runtime (lead tray «Coaxial cables & wires»: generic physical leads `S.pl` (coax probe / GEN coax / red / black banana: `{jack, clips:[{bn,bh}]}`), drag the head (snaps to a near compatible free jack) or tap it then a lit jack; `syncLeads` maps them onto the jack keys the labs read (`S.jack[g]`, `S.leads[k].node` = both ends in); step lines take `alt` when the manual names no unit/meter; auto plug-in lines in Manual steps; default layout from where each instrument's terminals face — top row / left / right of the panel, no crossings, `RT.crossings()` checks it; movable instruments with a four-way move handle (unplugged leads travel with their instrument), arrangement saved per experiment in localStorage, `ترتيب افتراضي` restores it; plug-in panel, two-leg parts and multi-pin parts — DIP-8 op amp, TO-220 / TO-126 transistors — with real looks, cables with labels / shadow / colour menu, hover glow, netlist, analysis, LEDs that blink with slow signals), `bench.js` shell (zoom, bag drawer, stepper, Manual/Free; PC tables), `hall.js` 3D scenes (the site opens at the corridor entrance; corridor ordered by study level from the registry — level signs, doors facing each other, closed "قريباً" doors for unbuilt labs — ending in the electives courtyard with its "عد إلى المقدمة" stand; any lab room built from its registry entry, with signs and an exit door back to the same spot), `quick.js` الوصول السريع (level → labs → experiments; a lab without experiments jumps to its door).
  - Steps: build steps carry `lines` (one connection per line: `{t, note, part|ic|lead|wire}`, ticked from the netlist, current one highlighted on the board; `fig` beside the step); `engine/bidi.js` isolates every English run in RTL text (test: `tests/exp/bidi.mjs`); `engine/fig.js` full-screen figures with pinch-zoom; `engine/welcome.js` + `labs/site.js` (author, linkedin, goatcounter); `engine/stats.js` GoatCounter events (off while the code is empty).
  - `breadboard.js` the Digilent breadboard panel (EE312 Exp 5 only, `board:'breadboard'`): posts ⏚ / Vc / Vb / Va, vertical rails, rail rows, 5-hole strips; parts and jumpers hole to hole (two taps), DIP-8 across the channel, «Jumper for a hook» stands in a hole and a coax mini-grabber clips onto its bare end, banana leads go on the posts. Line types add `{stub:node, n}`.
  - `spice.js` the PC table (Exp 6, 8): LTspice-style schematic editor (grid, R C L D V GND, op amps, nmos4/pmos4, wires, labels, directives incl. K, .lib, .step, .tran, .dc, .op), simulator on the engine solver, and waveform viewer (click node / drag node→node / click part, zoom, Ctrl+E, average). An experiment with `pc:true` gets this app instead of the bench; `onRun(RT,res)` lets it compare a run with reference circuits given as SPICE text (`RT.sim(text)`).
  - `labs/index.js` is the lab registry (data only, all 13 EE labs): code, name, `level` (5–8 or `'elective'`), room `{rows, cols}`, experiments (`bench` instruments, `built`). `engine/registry.js` gives lookups and lazy loading of `labs/<lab>/exp<N>.js`. An experiment file registers `EXP_DEFS['<lab>/expN']` with: `procs` ([{id,title}], the Manual procedure picker; steps take their procedure from a leading "Procedure X", sheet sections from `data-proc`, grading rows from `grader.proc(p)`), `sheet` (HTML), `params`, `instruments`, `parts`, `tray`, `setup(RT)` → `{status, steps, onReset}`. Adding an experiment = one file + `built:true`; adding a lab = a folder `labs/<id>/` + one entry in `labs/index.js`.
- Built: all ten EE312 experiments (Exp 6 and 8 on the PC table). Questions found while building and the decisions taken: `docs/ee312/QUESTIONS.md`.
- Tests: `node tests/e2e.mjs [desktop,phone] [modules]` (Playwright; set `THREE_JS=/path/three.min.js` if cdnjs is blocked). Every experiment has a full Manual run with full-marks grading in `tests/exp/`; `tests/pc.mjs` drives the PC app.

They replace Batch 4 item 2, the old "Wiring steps must be clear like the manual" rule and the old "Manual mode … graded at the end" rule (marked superseded below).
1. **A circuit counts when it works, however it is laid out.** A "build the circuit" step passes when the student's circuit IS the figure's circuit: the same parts (types and values), connected the same way, with the instruments at the right points (an ammeter in series in the right branch, a voltmeter across the right part, scope channels and their grounds on the right nets, polarity of diodes / electrolytics / meters right). Which panel nodes he used, how big or small or strange it looks does not matter. Check it by comparing circuits, not node numbers: the netlist of the bench vs the figure's netlist, tested for equivalence (graph isomorphism of nets, part types and values, instrument terminals). No check may ask for specific node numbers. Every experiment has a test that builds each circuit in at least two different layouts (different nodes and sizes), both pass, and wrong circuits (a missing part, a meter in parallel instead of series, a reversed diode) fail.
2. **"Build the circuit" is ONE step, with its figure under it.** The step says only what the manual says («وصّل الدائرة Fig. 5.4a»): no list of connections, no one-connection cards. The manual's figure is inside the step card, right under the step text (tap to enlarge, pinch-zoom), not in a side panel. One build step per figure, where the manual puts it. Connecting the instruments is its own step only where the manual has it as a step.
3. **Every other step follows the manual's procedure exactly:** one step per numbered step of the manual, same order, the manual's wording in Saudi Arabic with the English terms kept. A manual step with several actions shows them inside that step line by line. Never invent steps.
4. **Helpers «وصّل لي», «تلميح», «تخطّي»** (Manual and Exam modes; none in Free):
   - «وصّل لي» on a build step builds the whole current figure on the board (animated, part by part) and the step ticks, in the standard lab layout: start at the bottom-left node, up the left column, along the top row to the right, down the right column, back along the bottom row: a closed rectangle (e.g. 3–4 nodes high, 5 wide); series parts and bridging plugs on its sides in the figure's order, the source on the left side, parallel branches across the free nodes inside; instrument leads to their points from the side their instrument stands on, short, not crossing the board or each other. It should look like the figure (check against the lab's own circuits in the photos / video frames).
   - «تلميح» compares the student's circuit with the figure and says in one or two sentences what is wrong and where (R2 is missing; the ammeter is across R1 instead of in series; the red lead is in the 10 A jack; CH2's ground is not on ground; the diode is reversed), or which instrument setting is wrong when the circuit is right; it highlights the place on the board.
   - «تخطّي» skips the current step (short confirmation).
5. **Manual mode: no typing values, «Capture» instead.** A step that records something (a reading, a waveform on a figure, a table row) has a «Capture» button: it takes what the step asks for (the scope screen as an image, or the named meter's reading with its unit) and drops it under the step as «تسجيل 1», «تسجيل 2» … and into its place in the manual sheet (figure box, table cell). A step takes as many captures as the manual asks (e.g. a table of 9 frequencies = 9 captures); «اكتفِ بهذه التسجيلات وانتقل» moves on with fewer. Manual mode has no grading: the sheet fills itself from the captures and the student can read it back.

Exam shows the same procedure steps; the student types the values in the sheet and answers the questions, graded as before. The helpers are allowed but cost marks: the score is out of the number of graded steps of that experiment, every «وصّل لي» / «تلميح» / «تخطّي» takes points off, and the result card lists the helpers used and their cost. Free mode stays as it is.

## Interaction details (user requirements)
- **Movement by device:** WASD/arrows only on laptop/desktop. On iPad and phone, the student walks by tapping the floor (no keyboard hints shown there).

## Procedure picker in Manual mode (all labs, EE312 included)
- After choosing Manual, a small card lists the experiment's procedures (Procedure I, II, III, IV … with their titles) as a multi-select checklist, all ticked by default, with a note: «بعض الـ Procedures ممكن تكون محذوفة في ترمك، تأكد من دكتور المعمل واختر اللي مطلوبة منك».
- The student can tick any combination (e.g. I + III). Steps run procedure by procedure in order: when Procedure I is done a short "خلصت Procedure I ← ننتقل لـ Procedure III" card appears, then the next one starts. After the last selected one: the sheet (only the selected procedures' tables/questions) is filled and graded, then «قم من الطاولة».
- Unselected procedures are skipped in steps, sheet and grading. The step counter and progress show per procedure.
- Instruments can differ per procedure (EE205 Exp 1: Proc I uses three handheld meters, later procedures another set): an experiment file may give each procedure its own instrument list; the bench swaps them when the procedure changes.
